## Z-001 — Subject model: users, robot accounts, anonymous

`internal/authn`: `Subject{ID,Kind,Name,Disabled}` and one `Resolve` — an empty credential name means the request presented none and reads the anonymous row, so the only difference between a robot, a person and a stranger is which row is read. Disabled is a distinct sentinel from unknown (the client sees the same answer; whoever debugs it does not). The anonymous subject is now **seeded by migration 0002 in both engines and by `memory.New`** — "the anonymous subject exists" is part of the store contract, not one engine's detail, so `metatest` asserts it (reserved id `anonymous`, since bindings reference ids and a generated one would make an anonymous grant unportable). Disabling it is how an operator turns anonymous access off wholesale. Coverage 100%; CI green (run 33734466536)

## Z-002 — **Users + Argon2id credentials**

`internal/authn/{password,ratelimit}.go`. **Password:** Argon2id at OWASP's interactive cost (19 MiB, t=2, p=1), each hash carrying its own salt and parameters in the standard PHC string, so cost can be raised later without a migration and without invalidating one stored password — `NeedsRehash` reports the upgrade after a successful verify, which is the one moment the plaintext is in hand, and it only ever moves upward so lowering the configured cost cannot quietly downgrade everybody. Constant-time compare; the encoding is a **pinned golden** and the parse is strict by re-encode round-trip (Go's base64 tolerates newlines and non-zero padding bits, `strconv` tolerates leading zeros — one verifier, one spelling, the same lesson as Z-003a). A wrong password and a corrupt row are different errors. Tampering with the cost line invalidates the hash rather than weakening it, since the parameters are inputs to the digest. **Fuzzing found a real denial of service, twice:** the cost parameters come out of the stored hash, so a row reading `m=1000002100` asks for 954 GiB before any comparison — and then a second input showed a finite ceiling is not enough, since ~1 GiB × 20 passes is individually unremarkable and jointly twenty seconds per attempt. Bounded now by memory (256 MiB), iterations (16) and **their product** (512 MiB-passes, ~70× the default); both inputs are committed as regression seeds and 51.8M further executions are clean. **Rate limiting:** token bucket per account *and* per source address (ADR 0004) — each catches what the other misses, one account from a botnet versus one host spraying every account. Written as GCRA over a single timestamp rather than a token count, because floats answered `999.999999ms` for a one-second wait and a `Retry-After` should be true; all arithmetic is exact integer time. A refusal in one dimension spends nothing in the other, or an attack on one account would lock out everyone behind the same NAT. The key map is bounded (an unbounded one is memory exhaustion with no credentials at all) and **eviction drops the least-indebted key, never the least recently used** — the bucket worth keeping belongs to the attacker who exhausted their allowance and went quiet, which LRU would discard first, making key-spraying the way around the limiter. A test proves that; it caught the LRU version. Clock injected, no sleeps. **New quarantine rule** `password-hashing-is-quarantined` (archtest): `internal/authn` is the only importer of argon2/bcrypt/scrypt, so a second set of cost parameters cannot appear somewhere nobody is looking. No config keys yet — the limits are constructor arguments until the endpoints that need them land (Z-004, Z-020). Coverage 100% of `internal/authn`, 96.5% overall; CI green (run 33785190570)

## Z-003a — **Secrets encryption (`internal/secretbox`)**

Split out of Z-003 (F-005 precedent) because it is a separate package and the sole importer of the AEAD primitives, which Z-009's quarantine rule now enforces. AES-256-GCM, fresh 96-bit nonce per value, wire format `v1:<key-id>:<base64(nonce‖ciphertext)>` with a **pinned golden value** so a future build that changes nonce placement or encoding fails a test instead of orphaning rows. Context (AAD) is mandatory with no default and rejects a trailing `:`, so `ProxyCredential("")` cannot bind every row to one context. Multi-key keyring: first key seals, retired keys still open, `NeedsReseal`/`Rotate` drive the two-step rotation. `Redact` never returns ciphertext. Fuzzing found a real defect: Go's base64 decoder skips CR/LF and tolerates non-zero padding bits, so one ciphertext had many spellings — the parser now requires canonical encoding. Coverage 96.2%; verified independently (cross-row and cross-column AAD rejection, 200 distinct seals of one plaintext, no secret echoed in errors). ADR 0016 clarified: keyfile is base64-per-line, comments/blanks ignored, permission check strict with an opt-out for platform mounts, HMAC keying stays in this package; its stale `keys.secrets_key_file` corrected to `auth.secrets_key_file`. CI green (run 33731941016)

## Z-003b — Robot accounts: mandatory expiry, revocation

`internal/secretbox/mac.go` + `internal/authn/robot.go` + the robot branch in `server.BasicAuth` + keyring wiring in `serve`. **secretbox gains `MAC`/`VerifyMAC`** (the ADR 0016 clarification made real): HMAC-SHA-256 keyed by the secrets key, which never leaves the package; the digest records its signing key's id so **rotation covers digests exactly as it covers sealed values** — the new key signs, retired keys keep verifying, a ring without the key answers false (tested through a real `Rotate`). The context is length-prefixed (a boundary-shift test proves bytes cannot migrate between context and value) and binds by **robot id**, so a digest lifted from one robot's row cannot verify another's secret and renaming a robot does not orphan its credential. Pinned golden digest — a format change would strand every stored secret. **`authn.RobotSecrets`**: secrets are `trove_r_<robot-id>_<random32>`, shown exactly once (the store holds only the digest — asserted); one active secret per robot, so **minting again is rotation and the old secret dies at that moment**; revocation is the credential delete and wins on next use, not next mint; expiry is mandatory (90-day default, explicit values honoured, a past expiry refused at mint) and enforced on read by the store, so expired and absent are the same `ErrBadCredentials` as a wrong secret, an unknown robot, or a user's name — while a store failure stays a distinct failure. Rate-limited through the same `AttemptLimiter` as passwords. **`BasicAuth` dispatches on the `robot$` username prefix** (ADR 0004's naming), so robots authenticate at the same endpoints through the same guard — proven end-to-end by a robot minting a secret and running a guarded route as `robot$ci`. **`serve` now loads-or-creates the secrets keyfile** (Q21: generated 0600 on first boot with a log line — the live test asserts the file, the log, and that a restart loads rather than regenerates; an unreadable existing keyfile is fatal, never a fresh key over orphaned values). No §9 verb wired: the mint/revoke admin API arrives with the user-admin surface (U-007's server half). Coverage 96.3% overall; CI green (run 33794541314)

## Z-004 — OCI token flow (`WWW-Authenticate` / bearer)

`internal/authn/token/{jwt,key,scope}.go`, `internal/server/{api_token,api_v2}.go` + `Bearer`/`TokenChallenge`, serve assembly. **Tokens:** Ed25519 JWTs (`golang-jwt/jwt/v5`, quarantined to the token package by a new archtest rule — the algorithm allowlist that stops an alg-confusion forgery lives in exactly one place), verified with `WithValidMethods(EdDSA)` and pinned issuer/audience; the forgery table covers HS256-with-the-public-key, alg:none, a foreign Ed25519 key, tampering, and wrong iss/aud. TTL 5 m from `auth.token_ttl`, clamped 1–60 m in the constructor as well as in config validation. **Deterministic golden JWT** (fixed seed, injected clock and token-id source — Ed25519 signing is deterministic, so the whole token is pinned bytes). Signing key generated at first run beside the secrets key (`auth.token_signing_key_file`), 0600, O_EXCL, never regenerated over a corrupt file — same rule as the keyring, tested at serve level for both keys. **Scopes:** `repository:<name>:<actions>` parsed leniently (space-joined values, unknown types/actions and illegal names grant nothing and fail nothing), intersected via `authz.Allows` — the same call the handlers make — so **request wide, receive narrow** is proven: push requested on a read-only binding vanishes, an unheld repository vanishes entirely, and anonymous minting works with whatever the anonymous row's bindings grant (how public pulls bootstrap). **The token names the subject; authorization stays live**: a guarded route is re-decided per request, and the test revokes a binding mid-token-lifetime and watches the same bearer fail on the very next request (ADR 0004 §5, the Z-019 scenario). **Routes:** `/token` (public, frozen-approved) authenticates via the same `BasicAuth` — users and robots, rate-limited with a truthful 429 — and refuses an unknown `service`; `GET /v2/{$}` is the authentication probe per ADR 0004 step 1: 401 + `Bearer realm=…,service="trove"` challenge for anonymous (including a valid anonymous token — the probe's yes means "you are someone"), 200 disclosing nothing for anyone authenticated. **Frozen list grew to six** — the /v2/ entry supersedes Z-011's deferral note because ADR 0004 had already decided the behaviour; R-008 still owns the spec error-envelope. The realm follows `server.external_url`, or the client's own Host and scheme when unset. `Guard.Challenge` became per-request for the same reason. Disabled subjects: password refused at `/token` and an outstanding token refused at the probe. **The docker login sequence runs request-for-request against the real serve stack over live HTTP**: probe → 401 with a realm naming that very server → token via the bootstrap credentials → probe 200. **Deviation:** the acceptance's `docker`/`oras` binary integration and push/pull wait on Phase 3's content routes and R-009's harness — there is nothing to push into yet; the sequence-level proof stands in until then. Coverage 95.8% local (the key-permission branch runs on Linux); CI green (run 33796568741)

## Z-005 — **Permission vocabulary as typed constants**

## Z-008 — **`authz.Decide` pure decision function**

`internal/authz/decide.go`: `Decide(bindings, verb, resource) → Decision{Allowed, Verb, Resource, Matched}`. Pure — the caller resolves the subject to its effective bindings first (group expansion and the disabled check happen at fetch time), so the function sees only values. `Matched` lists every contributing binding, which makes the explainer (Z-013) this same call rendered differently rather than a second implementation that can drift; `Decision.String()` is the audit line. A verb outside the vocabulary is refused before any binding is consulted, so a row edited in the database cannot invent a permission. Five fuzzed properties: soundness/completeness against the definition, monotonicity (adding a binding never revokes), irrelevant-binding invariance, order independence (same answer *and* same explanation), and scope disjointness (repository bindings never reach `system`, and vice versa). No verbtest marks added: Decide is verb-agnostic, and marking from here would let a verb pass §9 without anything enforcing it. CI green (run 33730752671)

## Z-009 — **Import-boundary test for `internal/authz`**

`internal/archtest`: a generic allowlist checker over one `go list -deps -json` call, with six rules — authz reaches no storage package and no I/O package, the ADR 0009 cache↮gc/policy wall in both directions, and direct-import quarantines for Trivy (ADR 0017) and the AEAD primitives (ADR 0016). Transitive vs direct modes are distinguished because a transitive quarantine would flag `cmd/trove`'s own wiring, which must link the adapter. Non-test deps only, and a test pins that: `authz`'s external test imports `meta`/`sqlutil` for the differential scope test, and counting test deps would flag the very test that keeps the two matchers honest. Failures print the import chain. Verified by injecting a real violation into `internal/authz`, not only by the synthetic fixture module. Each rule is also fed a graph that breaks it, so a mistyped pattern cannot leave a rule silently dead. Coverage 99.2%. **Also fixes the coverage gate**: its `*test/` glob matched `internal/archtest` and silently dropped it from the denominator — harnesses are now named (`metatest`, `blobtest`, `verbtest`), §9 amended, with self-test cases both ways. CI green (run 33731147987)

## Z-010 — **Handler-level enforcement middleware**

`internal/server/{authz_middleware,bindings,router,errors}.go`: `Guard.Require(permission, handler)` resolves the subject, fetches its effective bindings, calls `authz.Decide`, and either serves or refuses — one path for everyone, anonymous included, since the anonymous subject is a row (Z-001) rather than a branch. **Registration is the enforcement point**: `Router.Handle` takes a `Permission` as a required argument and panics on an empty or unknown verb, and `HandlePublic` demands a written reason — a route cannot be left unguarded by omission, only refused in writing, and the reasons are what Z-011 walks. ADR 0003's disclosure matrix is a table test: unauthenticated → 401 + challenge; authenticated but unable to *read* the resource → 404, **byte-identical to the answer for a repository that does not exist** (asserted by comparing the two responses, not by asserting 404 twice); readable but not permitted the verb → 403. A resource extractor that rejects the request path → 400, never a decision. Every failure to *reach* an answer — store down, bindings unreadable, anonymous row missing — is 500, because a check that did not complete must not admit the request. `FetchBindings` skips a binding whose role has been deleted (only reachable by racing the delete; it grants nothing either way) but propagates a store error rather than returning the empty set, which would deny confidently instead of failing honestly. `ErrorRenderer` is an interface so R-008 can supply the spec's envelope on `/v2/` while the admin API keeps RFC 9457 problem+json. Takes `repo:read`, `repo:write` and `gc:run` off the §9 pending list — the first three verbs anything actually enforces. Coverage 96.1% of `internal/server` (100% of the four new files), 96.7% overall; CI green (run 33734466536)

## Z-011 — **Route-table guard test (fail closed)**

`internal/server/routes_guard.go` + `routes_guard_test.go`: `Router.Verify()` walks the assembled table and reports **every** problem, each naming its route — a route with no verb, a verb outside the vocabulary, a public route missing from the frozen `publicRoutes` list, or a public route whose registered reason has drifted from the approved one. Three closures, not one: (1) registration panics (Z-010); (2) `Verify`; and (3) **`ServeHTTP` will not dispatch a table `Verify` rejects** — every path answers 500 and logs the offending routes, which turns "somebody runs the check" into a property of the type. Frozen list is five entries (`/healthz`, `/readyz`, `/token`, `/{$}`, `/assets/{path...}`), each with a reason and the task that registers it; a test asserts each task ID exists in this file, each pattern is one the mux actually accepts, and the count is pinned so growth is reviewed. Approval is by exact method+pattern — a different method, a wildcard for a literal, or a deeper path under an approved prefix is not approved. **Deviation from the plan:** the plan said "walk the chi route tree", but Z-010 built the table on `http.ServeMux`, so the walk is over `Routes()`; and the plan's self-test ("register a guardless route in a fixture") is impossible through the public API since registration panics first — that case is covered by an internal test building the table directly, because a check that only holds because an earlier check ran stops holding when the earlier one moves. **The mux is quarantined**: an AST scan of every non-test file proves nothing outside `router.go` names `http.NewServeMux`, `http.Handle`, `chi.NewRouter` and friends, so no endpoint can be served from a table `Verify` cannot see; the scan counts the files it read (a walk that finds nothing would otherwise pass), has its own fixture self-test, and was verified by planting a real violation in `internal/cli`. `/v2/` is deliberately **not** pre-approved: whether the OCI base endpoint answers 200 or 401 anonymously is a disclosure decision for R-008. Coverage 100% of the new code, 96.5% overall; CI green (run 33771390212)

## Z-012 — **Permission-filtered query layer**

`internal/server/visibility.go` + metatest additions. Most of this task landed with its prerequisites: every listing the store offers has taken a mandatory `Visibility` since F-005 (the zero value shows nothing), both engines compile it into the WHERE clause through the one shared `sqlutil.VisibilityClause`, and no unfiltered variant exists to call. What was missing was the production bridge from a subject's bindings to that Visibility: `VisibilityFor(bindings, verb)` composes `authz.VisibleScopes` → `authz.Filters` → `meta.ScopeFilter`, so a listing and a `Decide` call start from the same bindings (ADR 0003). It lives in `internal/server` beside `FetchBindings` — the plan's file list named the meta engines, but the bridge cannot live in `authz` (Z-009 forbids the meta import) and the engines already had their half. **Never Unrestricted:** a subject bound to `*` gets an all-matching filter through the filtered path; `Unrestricted()` stays reserved for subjectless internal callers (migrations, GC). The authz differential tests — including the matcher-vs-SQL fuzz target — now run **the production bridge** rather than a test-local sketch, so the three readings of a scope (matcher, SQL predicate, compiled Visibility) are pinned together through the code listings actually call. metatest grows two cases all three engines run unmodified: pagination with hidden repositories interleaved at page boundaries (stitched pages equal exactly the visible set, and **a `NextCursor` may never name a hidden repository** — the cursor is part of the response and would disclose as surely as listing), and keyset-cursor stability under mid-walk writes (rows created behind the cursor are not revisited, hidden rows never appear, nothing that existed is skipped or repeated). A full-pipeline test — subject → `FetchBindings` → `VisibilityFor` → `ListRepositories` against a real store — carries the §9 marks and takes **`repo:list` off the pending list (26 left)**; its verb-negative case is a subject whose `*`-scoped binding lacks the verb, so scope breadth cannot stand in for the grant. Search, event and metric listings do not exist yet; they compile from this same bridge when E-010/E-002/E-005 land, and Z-018 walks them. `VisibilityFor` 100% covered; 96.6% overall; CI green (run 33787538572)

## Z-013 — **Effective-permission explainer** (CLI + API)

`internal/server/api_auth_explain.go` + `internal/cli/auth.go`. `GET /api/v1/auth/explain?subject=&verb=&resource=` is `authz.Decide` rendered — the matched bindings in the response are the bindings that would admit the real request, each named with its role, scope and the group it came through, so the explainer cannot drift from the decision it explains (ADR 0001). The response also carries the subject's `disabled` flag, which is what turns "the grant is on the books but nothing works" from a ticket into a sentence. **New guard concept, `Permission.Self`**: the explainer is the first of a class of routes about a *subject* rather than a repository (password rotation, own tokens, U-002's endpoint follow), so "self is always allowed; anybody else needs the verb at system scope" (ADR 0003 surface 8, `user:read` here) is declared at registration and enforced in the one guard path — not hand-checked in the handler. `Self` is mutually exclusive with `Resource` (registration panics), its extractor's failure is a 400 like a resource extractor's, and a self-admitted request carries no Decision in context because nothing was decided — the rule is structural. **Disclosure**: the refusal for explaining others happens before any target lookup, so the 403 is byte-identical whether the target exists or not (tested by comparing the two answers); anonymous asking about others gets 401 + challenge; with `user:read` an unknown subject is a 404; a store that cannot answer is a 500 in both the guard and the handler — an explainer that renders "denied" off a broken store would send an operator hunting for a binding that exists. Golden-tested wire contract. **CLI** `trove auth explain --subject --verb --repo [--json]` is a client of the endpoint (Q23) tested against the real router and handler, formatting only: problem details relayed verbatim, `--json` passes the body through untouched, `TROVE_TOKEN` rides as a bearer header so the command works unchanged when Z-004 lands. Takes **`user:read` off the §9 pending list (25 left)** — the plan had predicted Z-014 for it, but ADR 0003 surface 8 puts its first enforcement here; `role:read`'s entry (predicted for Z-013) now names the role admin API that will actually wire it. **Deviations:** no `internal/authz/explain.go` (Decision *is* the explainer — a second rendering there would be the drift ADR 0001 forbids) and no `cmd/trove/auth_explain.go` (dispatch lives in `internal/cli` since F-001); the route registers through the Router and is mounted into `trove serve` when Z-014 assembles the real server around an open store — serve still runs the placeholder handler today. Coverage 96.5% overall; CI green (run 33789226749)

## Z-014 — Admin bootstrap + forced first-login rotation

`internal/authn/{bootstrap,login}.go`, `internal/server/{basic_auth,api_auth_password}.go`, guard additions, `serve` assembly. **Store:** new `meta.PutBuiltinRole` (interface + all three engines + contract case) — the only path that changes a built-in role, because operators cannot edit them but startup must bring "admin means every verb" back to true after an upgrade or a row edited in the database. Replacement keeps bindings; the contract proves an engine modelling it as delete-and-recreate would cascade every admin binding away. **Bootstrap:** built-ins converge on *every* start (set-compare, then put; a custom role squatting a built-in name fails the boot loudly — a deployment whose "admin" is not the admin role is misconfigured in the worst way). The admin is created exactly when nobody could log in otherwise: a fresh store, or a **torn first boot** (the admin user exists without a credential — a crash between subject and hash would otherwise strand the deployment with no further boot touching it). Writes tolerate their own prior success; the credential lands last with no tolerance, because its absence is what "still torn" means. Password: 24 random bytes, 32 URL-safe chars, printed **once to stdout, never the log stream** (the live test greps the logs for it), `MustRotate` set — never a default credential. **Login path:** one `authn.PasswordLogin` shared by basic auth now and the token flow/UI later — Z-002's GCRA limiter in both dimensions with a 429 whose `Retry-After` is proven honest (the test waits exactly the stated seconds and succeeds), a **decoy verifier burned for unknown users** so response time does not enumerate accounts, corrupt row ≠ wrong password (500 vs 401), and the `NeedsRehash` upgrade wired at the one moment the plaintext is in hand — best-effort, proven not to fail a login when the store has gone read-only. **Gate:** `Guard.Rotation` refuses a must-rotate user on every route except those marked `RotationExempt` at registration; fails closed on an unreadable credential; only users are checked (robots and token-only users have nothing to rotate). The refusal names its own exit (`rotation-required` problem with the endpoint in the detail). **Rotation endpoint** `POST /api/v1/auth/password`: a `Permission.Self` route (always the caller; resetting others is the user-admin API's job under `user:write`); knowing the current password authorizes the change and is verified through the login path so it is rate-limited like one; new password ≥8 chars and ≠ current; sessions die with the old password (a failed sweep is logged, not unrotated — the new password is already real). The assembled-table test pins **exactly one** rotation-exempt route and zero public ones. **`trove serve` is real:** opens the configured engine (sqlite default, postgres by DSN; `--no-auto-migrate` honored at the store), bootstraps, prints the credentials, serves the guarded router — the placeholder is gone, and unregistered paths 404 until their tasks land (`/healthz`/`/readyz` with E-007, `/v2/` with Phase 3). The live test walks the acceptance story over HTTP: first boot prints a password that opens nothing but the rotation door, rotating opens everything, the old password is dead, and a restart prints nothing. **Verb bookkeeping:** no §9 verb comes off — the route registers `user:write` but never consults it (self-only), so the allowlist entries for `user:write`/`role:read` now name the user/role admin API (U-007's server half) instead of tasks that turned out not to enforce them; the plan's prediction that Z-014 wires `user:read` was overtaken by Z-013 (ADR 0003 surface 8). UI half of forced rotation lands with Z-020. Coverage 96.3% overall; CI green (run 33793084990, after a gofmt-only fix — `make lint` does not run CI's gofmt step)

## Z-015 — Self-lockout prevention

`internal/authz/lockout.go`. The pure half of the §5 rule, in the package the plan placed it: `AdminGrant` (does this binding set grant `role:write` at `system` — breadth is not administration, so a `*`-scoped grant does not count, by scope disjointness), `EnsureAdminRemains` (refuse any post-change state in which no enabled subject holds it, with `ErrLastAdmin` whose message says what to do — the API surfaces it verbatim), and the `Without{Binding,Role,Group}` simulation helpers that turn each removal vector into a one-line post-state over `FetchBindings` output. The adversarial table drives a real store through **every §5 vector**: deleting a binding, deleting the role (whose bindings cascade), removing a group membership — the vector the plan calls out, counted exactly like losing a binding — deleting the group, deleting or disabling the subject (absent from the post-state, since a disabled subject has no effective bindings), and **narrowing the role's verbs**, the subtle one where every binding survives and none of them matters; plus the two-admins-remove-one and redundant-double-grant success cases. **Deviation, stated rather than silent:** no mutation endpoint for bindings/roles/subjects exists yet, so there is nothing to wire the check into — the enforcement contract is that C-016/U-007's mutation handlers call `EnsureAdminRemains` inside their transaction before committing, and Z-019's suite drives the end-to-end scenario when they land; the doc comment carries that contract. `role:write`'s §9 allowlist entry relabeled to the role admin API accordingly (the lockout tests are not verb enforcement, same reasoning that kept Z-008 from marking). Coverage 100% of the new file, 95.8% overall; CI green (run 33800223708)

## Z-019 — **Privilege-escalation adversarial suite**
