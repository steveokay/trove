## E-001 — In-process event bus + typed taxonomy + transactional outbox

**Taxonomy** (`internal/event/types.go`): a closed `Type` set with `Valid()` and `Types()` so E-002/E-004/E-005 enumerate rather than re-list it. Sixteen types — CLAUDE.md §8's thirteen plus `group.member.skipped` (C-011 emits it) and `cache.stale-served` + `blob.corrupt`, which §8 omits but **ADR 0012's taxonomy names**; the ADR is the specification, and both were verified present there during reconcile before the expansion was accepted. Every type has a payload struct implementing `Payload{EventType() Type}`, which makes an event whose body disagrees with its type unconstructable. Timestamps are forced to UTC so the same event signs to the same HMAC anywhere. The golden per type is a **round trip** (marshal → compare → decode → DeepEqual), so a field that encodes but does not decode fails rather than passing; companion tests fail if a new type arrives without a golden or without a decode case.

**Bus** (`bus.go`): handler registration, not channels — and the reasoning is the good kind. A panicking channel *reader* panics on its own goroutine, where the bus can never observe it, so ADR 0012's required consumer-panic-isolation test would have had nothing to assert; with handlers the bus owns the goroutine and can recover. Each subscriber gets its own buffered queue and goroutine; `Publish` does a non-blocking send per subscriber and a full queue increments per-consumer and bus-level counters, logged with the queue depth when the consumer next moves (the `pullstats` precedent: count, don't flood). Handlers receive `context.WithoutCancel` of the publishing context, so request values travel but request cancellation does not — a returned request cannot kill an outbox insert. Panic isolation and drop-on-full are both tested deterministically with no sleeps: the panicking consumer still receives subsequent events, a bystander receives everything, and the publisher never blocks behind a stuck consumer.

**Outbox** (`outbox.go` + `meta.Store.WithinTx`): the durability half, and the design decision worth recording. The brief offered `AppendEvents(ctx, []Event)` as the smaller change; the agent rejected it with the right argument — **no caller of `meta.Store` owns a transaction today**, every method opens and commits its own, so there is no existing transaction for a caller to append inside. `AppendEvents` could therefore only have delivered an atomic *batch*, and ADR 0012's crash test would have degenerated into "a batch with one bad member writes none of it": true, useful, and not the guarantee. `WithinTx(ctx, func(tx meta.Tx) error) error` delivers the real rule — an event row exists iff the transaction that produced it committed — and has a testable failure mode. `meta.Tx` is deliberately one method wide (`AppendEvent`) rather than mirroring ~30 write methods across three engines, most of it dead until callers exist; the doc says so, so it reads as a decision rather than an omission, and `PutManifest` moves onto `Tx` whenever a task first needs a manifest and its `artifact.pushed` to commit together. **Migration 0006** creates `events` in both engines with **no foreign key on `repo_name`** — an event is an observation and `artifact.deleted` must outlive the repository it names, which a contract case proves. `payload` is BLOB/BYTEA rather than a JSON type because it is the signed webhook body and must return byte for byte. `ListEvents` filters by visibility in the query, and system events (NULL repository) are returned only to `Unrestricted()` — including *not* to a `*`-scoped subject, since the per-type verb such an event needs (`audit:read` for `authz.denied`) belongs to E-004 rather than to a query that knows only names.

**Reconcile:** wired into serve — bus constructed, outbox subscribed, and `bus.Close` draining **before** the deferred `store.Close`, since a drain into a closed store loses exactly the events a shutdown is most likely to be asked about. `go vet`'s `lostcancel` caught that the new fallible setup sat between the upload reaper's `context.WithCancel` and its cancel, so an error return would have leaked the context; the bus setup was hoisted above the reaper so no fallible step separates the two. Emitting events from existing call sites is each owning task's job, not E-001's: the seam exists, nothing is threaded through it yet, and R-010's `artifact.pulled` emit is noted at the batcher. Coverage 95.5% overall, `internal/event` at 100%.
