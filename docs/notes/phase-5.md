## S-001 — `scan.Scanner` interface + fake

The interface is frozen here for the whole scanning phase, with one **deliberate departure from ADR 0017's code sketch**: `UpdateDB` is split out as `DatabaseUpdater` and recomposed with `Scanner` as `Engine`. Nothing an implementation provides changed — only which callers must depend on what, and the queue (S-003), rescan (S-005) and gate (S-011) depend on `Scanner` alone, which never needs to update a database. `Name()`/`Version()` take no context because they answer from memory and are stamped on every report — a finding nobody can attribute to an engine version is a finding nobody can reproduce — while `DatabaseVersion` does take one, since an air-gapped import can replace the database underneath it. `DatabaseVersion.Changed` compares the **ID only**, so a restart that re-reads the same database at a later time does not re-enqueue the entire registry. `Target` is two strings with no storage import; its validation reuses `internal/reponame` (one grammar, shared with binding patterns and the router) and checks the digest for *shape* only, leaving parsing to the layer that dereferences it.

**The frozen call contract**, documented on the interface itself: a nil error means `StatusSucceeded` and that is the only outcome readable as clean; an error wrapping `ErrScanFailed` also returns a `StatusFailed` report describing the attempt, so a caller can record the failure without reconstructing one. `Report.Clean()` is the only way to ask whether an artifact passed, deliberately — `len(Findings) == 0` is equally true of a scan that never ran, and that conflation is exactly what `unscanned: block` exists to catch. `Report.Failed(cause)` clears findings, because a partial list stored as a result is a clean bill for whatever it did not reach.

**The normalised model** carries our types only. `Severity` is closed and ordered with `Compare`/`AtLeast`/`ParseSeverity` — parsing rejects `moderate` and typos rather than silently degrading a policy threshold — and `Finding` mirrors ADR 0006's `findings` columns exactly. `Rollup` is field-for-field identical to `event.SeverityCounts`, same names, tags and order, **with a reflection test that fails if either side drifts**: the scan report and the `scan.completed` webhook payload cannot diverge without a red build. `Worst()` returns a second boolean rather than a sentinel, since "no findings" is not a severity and a gate must not be able to compare against one. `Stale`/`Age` are ADR 0013's `scan-stale` input, pure with an injected clock and negative ages clamped so clock skew cannot defeat the bound.

**The fake never invents an outcome.** An unscripted digest returns `ErrNotScripted`, which deliberately does *not* wrap `ErrScanFailed` — a missing test line and a broken scanner are different problems, and conflating them would let a gating test pass for the wrong reason. It validates its own scripted output, so an impossible report is refused rather than quietly training a downstream test against something no adapter could produce. Latency is *recorded* in the report rather than slept; a test that needs a scan genuinely in flight injects a wait channel. `Options.Fallback` is the explicit opt-in for volume tests that do not want to script every digest.

**Quarantine**: the existing `trivy-is-quarantined` archtest rule was broadened from three Trivy module paths to the whole `github.com/aquasecurity/...` tree (the sibling modules Trivy's API hands back are vendor types too) plus Grype and Claircore. It is **proven to bite** in the Z-009 style — synthetic graphs where `internal/scan`, the fake, `internal/policy` and `internal/registry` import a vendor package each produce exactly one violation citing ADR 0017; the adapter and its future subpackages are exempt; near-miss names like `scan/trivyx` are not; and the vacuous pass against the real module graph is asserted to have actually loaded `internal/scan`, so a green result is not an empty one.

**Two ADR ambiguities were surfaced and resolved into an ADR 0017 clarifications section** (the precedent is ADR 0016's, added during Z-003a). First, ADR 0017 maps vendor-unknown severity to `low` while ADR 0012's payload carries an `Unknown` bucket: both stand, because the adapter never emits `unknown` while `trove db import` (Q6) and `trove migrate --from` (Q17) carry data whose severity vocabulary belongs to somebody else, and re-labelling that as `low` would be a claim the importer cannot make. Ranking `unknown` lowest means imported data fails a threshold open rather than blocking a pull on an unclassified CVE, consistent with gating being observed before it is enforced (Q12). Second, `Report.Status` stays two-valued; a third "unsupported" state was rejected because ADR 0013 gives it no gating meaning, and the distinction the adapter must make instead is now written down: an artifact that is **not an image** (signature, SBOM, attestation — `artifact.Kind` says which, R-007) is succeeded-with-no-findings because it genuinely has none, while an **image the scanner cannot analyse** is `failed`, since reporting it clean would publish a bill of health for something nobody examined. S-002 branches on kind before it branches on the vendor's error. Coverage 95.8% overall; both new packages at 100%.
