## R-001 — Blob upload (monolithic, chunked, resumable)

`internal/registry/{errors,blobs,uploads}.go` + `internal/server/oci_routes.go` + serve wiring — Phase 3 opens. **Routing first:** OCI paths carry multi-segment repository names, which `ServeMux` patterns cannot express, so the Router gains `HandleOCI(method, suffix, permission, handler)` — end-anchored suffix matching (longest wins, so `/blobs/uploads/{id}` beats `/blobs/{digest}`, and a repository legitimately named `team-a/blobs` routes correctly), living **inside the Router**: the routes sit in the same verified table with the same one-verb registration rules, because a dispatcher beside the mux is exactly what the quarantine exists to prevent. A slash-bearing traversal in a placeholder cannot even route; the handler's upload-id allowlist is the second wall. **Error contracts split by path** (`server.SplitErrors` + `registry.SpecErrors`): the /v2/ tree speaks the spec envelope for every refusal — including the guard's 401-with-challenge, the byte-identical 404, and the must-rotate DENIED that names its exit — while the admin API keeps problem+json; R-008 grows the goldens from the renderer table here. **The upload API:** POST start (202, `Location`, `Range: 0-0`, `Docker-Upload-UUID`) / monolithic (`?digest=`, 201) / cross-repo mount (`?mount=&from=` gated on live `repo:read` of the source, and **every failure — unreadable source, absent source, absent blob, malformed anything — falls back to an identical 202**, so the mount cannot probe existence); PATCH chunks with `Content-Range` continuity (416 on out-of-order); PUT commit with optional final chunk — **digest verified by the driver, and a mismatch publishes nothing and forgets the session**, no blob, no row, no retry into half-verified state; GET status; DELETE cancel; HEAD/GET blob streaming through `VerifiedReader`. Upload **rows land before sessions and blob rows before row deletion** (ADR 0010: content is pinned or recorded at every instant); sessions are **repository-bound by their row**, so an id replayed under another writable repository answers unknown; a row whose staged bytes vanished answers unknown too (restart → client re-pushes). Concurrent same-digest pushes both succeed; proxy repositories answer DENIED by type (ADR 0005); an absent repository and a hidden one answer byte-identically; a store that cannot answer is a spec-shaped 500, never a confident "unknown"; meta↔blob drift on read is a 500, never a lie (P-012's scrub). Quota is the stubbed `QuotaChecker` seam — a refusing stub proves start, monolithic, and chunk paths all consult it (P-009 lands enforcement without handler changes). **serve wires the hosted half** of fs or S3 storage at a disjoint root chosen at wiring time (ADR 0009); the live test proves the /v2/ tree speaks the spec envelope over real HTTP (the unrotated admin's push refused as DENIED naming the rotation). **Deviations:** blob-existence disclosure via HEAD is accepted — ADR 0006's `blobs` table is global by design, digests are content hashes, and probing still requires a readable repository; the official conformance suite runs with R-009 (a live full push additionally waits on C-016's repository-creation API — repositories are explicit entities, and none can be created over HTTP yet). Coverage 95.3% overall; CI green (run 33803412338)

## R-002 — Manifest put/get/delete + media-type validation

`internal/artifact/{mediatypes,parse}.go` + `internal/registry/manifests.go` + `registry.max_manifest_bytes` (config, default 4MiB) + serve wiring. **The parser is the edge** (`internal/artifact`): a closed set of four manifest media types (OCI manifest/index, Docker v2 manifest/list — schema 1 refused by absence), Content-Type and payload `mediaType` must agree where both exist and either may stand in for the other, every descriptor digest passes the strict allowlist parser before it can reach a query, and `subject` is honored **only on OCI types** — the Docker schema has no such field, and honoring one there would create attachments no Docker client asked for. `artifactType` resolves per spec v1.1: the explicit field, else the config media type (which is how a helm chart labels itself with no special casing). Foreign layers (`urls`) are marked external: not verified, not edge-recorded — the registry neither stores nor GCs them. **PUT** caps the payload before parsing (`MANIFEST_INVALID` naming the limit), computes the digest in the reference's own algorithm so a sha512 push cannot be mis-stored, refuses a mismatched digest reference with nothing published, and verifies **every referenced blob and index child exists** before the write — `MANIFEST_BLOB_UNKNOWN` naming the missing digest — plus a descriptor whose size contradicts the blob row (`MANIFEST_INVALID`; a size that lies breaks clients). The subject is deliberately exempt (spec: attachments may arrive before their subject) and echoed in `OCI-Subject`. Manifest and edges land in one transaction (ADR 0010); the tag repoints after. **GET/HEAD** serve the exact stored bytes under the stored media type and re-hash the payload on the way out: a row that no longer matches its digest is a 500, never content, and a tag pointing at a vanished row is the same 500, never "unknown" (ADR 0007; P-012's scrub). **DELETE** is digest-only (by tag answers `UNSUPPORTED` — tag deletion is R-003's, and the message says to use the digest); it collects the transitive referrer tree, pre-checks **Q10 across the whole tree and fails closed before deleting anything** — a member still listed by a live index outside the tree refuses the cascade naming that index — then deletes deepest-first (the signature dies before the SBOM, the subject last), so a crash mid-walk leaves only orphans for GC's sweep, never a dangling reference (ADR 0011); a store-level `ErrReferenced` race gets the same DENIED. Cascade proven three levels deep with the tag gone; index delete releases children for individual deletion. **Verbs:** `manifest:delete` enforced at the route — carol with `repo:write` and rita with `repo:read` both refused, anonymous gets the challenge — taking **`manifest:delete` off the §9 pending list (24 left)**. Hidden and absent repositories answer byte-identically on every manifest route; proxy repositories refuse PUT and DELETE by type (message generalized to "does not accept client writes" since deletes are writes too). Every store failure is a spec-shaped 500 through the same faulty-store harness as R-001. **Deviations, stated:** the per-referrer cascade audit records ADR 0011 asks for await the audit log (E-009 — `internal/audit` is still a doc stub), and `artifact.pushed`/`artifact.deleted` events await the bus (E-001); the enforcement contract is noted here rather than silently dropped. Coverage 95.3% overall; CI green (run 33873869803)

## R-003 — Tag list + pagination (permission-filtered)

`internal/registry/tags.go` — `GET /v2/<name>/tags/list` under `repo:read` (ADR 0002: listing tags is reading the repository). The page is a filtered query end to end: bindings → `VisibilityFor(repo:read)` → `ListTags`, with the store's not-found — unreadable and absent alike — mapped to the byte-identical guard 404, proven body-and-headers in both the handler suite and the now-unskipped Z-018 surface-2 test (`test/disclosure/tags_test.go` runs the real guard + real handler; **"tag list endpoint" off the disclosure skip-list**). Pagination is the spec's `n`/`last` with keyset cursors: a 25-tag stitching test proves pages concatenate to the full lexical set with no duplicates or gaps and no `Link` on the last page; `n` is echoed in the `Link` only when the client sent one, its query values escaped because a cursor is stored data being concatenated into a URL; `n=0` and absent both mean the store default (a zero page with a cursor is an infinite loop, not an answer), and a present-but-malformed `n` is a 400 `UNSUPPORTED` rather than a silent different page size. Empty repository answers `"tags":[]`, never null. A missing context subject fails closed to an empty visibility (no branch that could be wrong in the unsafe direction); a repository vanishing between resolution and listing answers the ordinary 404, not a 500. Store failures are spec-shaped 500s through a tags-local faulty store. Built by a parallel worktree agent against the frozen R-001/R-002 seams; reconciled with serve wiring here. **Deviation/left-open:** tag *deletion* (the spec's `DELETE /v2/<name>/manifests/<tag>`) remains `UNSUPPORTED` from R-002 — the route table's one-verb-per-route rule cannot express tag-vs-digest verb selection on a single route, so wiring `tag:delete` needs a deliberate routing split (constrained reference matching → two routes, one verb each), noted on the §9 allowlist entry; protected-tag gating belongs to P-001 regardless. No new verb marks (repo:read was already covered both ways). Coverage 95.1% overall; CI green (run 33878829309)

## R-004 — Catalog endpoint (permission-filtered)

`internal/registry/catalog.go` — `GET /v2/_catalog` as the first **Listing route**: the guard (new `Permission.Listing`, landed as fan-out groundwork in 72ebd7d) compiles the subject's bindings into the Visibility `repo:list` grants and hands it to the handler via `VisibilityFrom`, so there is no unfiltered read to forget to filter — counts and cursors come out of the same filtered query (ADR 0003 surface 1; **"catalog endpoint" off the disclosure skip-list**, its suite driving hidden repositories planted exactly on page boundaries through the real guard and asserting full pages, clean cursors, and the spec-envelope anonymous 401). Anonymous with nothing visible gets the 401 challenge (it may authenticate into visibility); an authenticated subject with no `repo:list` anywhere gets the literal `{"repositories":[]}` — an empty page disclosed nothing, and scope breadth without the verb stays nothing (the Z-012 reading, re-proven at the route). Every repository type is listed — hosted, proxy, group are all pullable endpoints; ADR 0005's per-type *content* semantics arrive with the Phase 4 router and are noted in a code comment rather than half-built. Pagination is `n`/`last` with the store's keyset cursors; `n` echoes into `Link` only when client-sent; malformed `n` is a named 400, not a silent different page. **Deviation, reasoned:** `Catalog` is itself the `http.Handler` so the no-Visibility fail-closed branch — the one invariant that must refuse rather than answer a plausible page — is directly testable instead of three permanently dead statements. Built by a parallel worktree agent (which fast-forwarded its worktree to pick up the groundwork commit); reconciled with serve wiring here. **Both repo-walking guard tests (verbtest scan, Z-011 mux quarantine) learned to skip dot-directories during this reconcile** — each was reading the agents' unmerged worktrees under `.claude/worktrees` as if they were the tree, the second one masked by Go's test cache because out-of-package file reads are invisible to cache keys. No new verb marks (repo:list covered both ways since Z-012). Coverage 95.1% overall; CI green (run 33878829309)

## R-005 — Referrers API (v1.1)

`internal/registry/referrers.go` — `GET /v2/<name>/referrers/<digest>` under `referrer:read`, with the ADR 0002 conjunction enforced in the handler: `repo:read` on the repository holding the subject is checked through the same bindings a pull would use (the `mount` sub-decision pattern), and its refusal is the byte-identical hidden 404 — **checked before the digest even parses**, so a malformed digest against an unreadable repository cannot confirm the repository exists. The §9 case is a named test both in the handler suite and in the now-unskipped Z-018 surface-3 test (**"referrers listing" off the disclosure skip-list**): a subject holding `referrer:read` without `repo:read` asking about `secret/vault` gets an answer indistinguishable, body and headers, from asking about `secret/absent` — an SBOM inherits its image's permission. Response is an assembled (never stored) OCI image index; descriptors carry mediaType/digest/size always and artifactType/annotations by `omitempty`, annotations lifted from the stored payload by a one-field unmarshal in the handler (`internal/artifact` stays about what the registry validates); `manifests` renders `[]`, never null, including for a digest never pushed — the spec's answer and the disclosure-safe one. `?artifactType=` filters via the store's indexed query with `OCI-Filters-Applied` set exactly when a filter was applied, matches or not. Full-body golden pinned; **`ListReferrers`'s digest ordering promoted from accident to contract** during reconcile (interface doc + metatest assertion — all three engines already complied) because a golden over store-dependent order would make identical registries answer differently. **`referrer:read` off the §9 pending list (23 left)**, positive at the round trip, negative at rita's 403 (readable-but-unattached refusal). Anonymous gets the challenge; bindings-store failure during the sub-decision is a fail-closed 500. Built by a parallel worktree agent; reconciled with serve wiring here. Coverage 95.2% overall; CI green (run 33878829309)

## R-006 — Multi-arch index handling

Gap-closing over R-002, which had already landed every R-006 behavior: child edges on index PUT (OCI and Docker list alike), `MANIFEST_BLOB_UNKNOWN` for a missing child, the Q10 `DENIED` naming every referencing index, index deletion releasing children, and verbatim payload service (platform selection stays the client's — the registry never reads `platform`). The verification was against the code, not the notes, and produced **no production gap and no `internal/artifact/index.go`** — the plan's predicted file predates R-002's parser. What R-006 adds is the adversarial delete-order matrix (`internal/registry/index_test.go`, all identifiers `index`-prefixed): two indexes sharing a child (refusal names both, then the survivor, then releases), nested index-in-index (deletable outer→inner→leaf and no other order), a Docker manifest list under the same rules, index deletion killing its own tag while a child's direct tag keeps serving, rich-platform byte-identical round-trip by tag and digest, and re-push-after-delete recreating edges. **The mutation-testing find:** neutering the handler's `refuseIfIndexed` pre-check failed no existing test — R-002's cascade fixture had the blocked member deepest, so the store's per-delete check masked the handler's. The new `TestIndexedSubjectFailsCascadeClosed` puts the index child at the cascade root, where a deepest-first walk without the pre-check would delete the SBOM and signature before refusing; it is the only test that fails under that mutation. **Reconcile addition:** index child descriptors are now size-checked against the stored child manifest exactly as blob descriptors are (`MANIFEST_INVALID` naming digest and sizes) — the agent flagged the parity gap and the reconciler closed it in the same commit. Deferred, explicitly: the GC-interaction fixture (released children sweep after grace) needs P-007's GC and lands there; real `oras`-built fixtures are R-009's conformance job. Coverage 95.2% overall.

## R-008 — Spec error-code mapping

The /v2/ wire error contract, golden-tested: 24 files under `internal/registry/testdata/errors/` in a canonical form (status line, sorted headers, body verbatim, LF-pinned). Nine renderer shapes cover every `SpecErrors` method **and the branches that change bytes** — the empty-challenge Unauthorized (no `WWW-Authenticate` at all) and the Retry-After floor (0 → `1`, so a refactor cannot emit `Retry-After: 0` and invite a retry storm). Fourteen envelopes pin one representative rendering per `Code*` constant with messages drawn from real call sites, and one golden pins `encoding/json`'s HTML escaping (`<`…), which is real wire behavior nobody chose but clients now parse. **The ratchet parses `errors.go` with `go/ast`** rather than trusting a hand-kept list, cross-checks both directions (new constant with no golden fails; stale row for a deleted constant fails), and was proven live by injecting a `CodeSizeInvalid` and watching it fire. Companion tests reject orphan golden files and re-decode every committed body as the strict spec envelope with UPPER_SNAKE codes — so a bad `-update` is caught, not enshrined. `-update` regenerates (`go test ./internal/registry/ -run Goldens -update`); the writing function is the only file-touching one and the read-back validators skip under the flag to avoid racing it. `errors.go` changed by 13 purely-additive lines (the exported `WriteSpecError` delegation the external test package needs); every pre-existing test passes unmodified, which is the no-rendered-byte-changed proof. Z-018's hidden-vs-absent byte-identity is referenced, not duplicated — this suite pins what a refusal looks like, that one proves two refusals look the same. **Follow-ups proposed, not done:** `failures_test.go`'s renderer test is now strictly superseded and can be deleted by a commit that owns that file; the plan's "one constructor per code" would have to canonicalize today's per-site messages (DENIED alone has four), a behavioral choice for a dedicated pass — these goldens are the net that makes that migration safe, and `WriteSpecError` should be re-unexported when it lands. Coverage 95.2% overall.
