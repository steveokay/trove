## R-001 — Blob upload (monolithic, chunked, resumable)

`internal/registry/{errors,blobs,uploads}.go` + `internal/server/oci_routes.go` + serve wiring — Phase 3 opens. **Routing first:** OCI paths carry multi-segment repository names, which `ServeMux` patterns cannot express, so the Router gains `HandleOCI(method, suffix, permission, handler)` — end-anchored suffix matching (longest wins, so `/blobs/uploads/{id}` beats `/blobs/{digest}`, and a repository legitimately named `team-a/blobs` routes correctly), living **inside the Router**: the routes sit in the same verified table with the same one-verb registration rules, because a dispatcher beside the mux is exactly what the quarantine exists to prevent. A slash-bearing traversal in a placeholder cannot even route; the handler's upload-id allowlist is the second wall. **Error contracts split by path** (`server.SplitErrors` + `registry.SpecErrors`): the /v2/ tree speaks the spec envelope for every refusal — including the guard's 401-with-challenge, the byte-identical 404, and the must-rotate DENIED that names its exit — while the admin API keeps problem+json; R-008 grows the goldens from the renderer table here. **The upload API:** POST start (202, `Location`, `Range: 0-0`, `Docker-Upload-UUID`) / monolithic (`?digest=`, 201) / cross-repo mount (`?mount=&from=` gated on live `repo:read` of the source, and **every failure — unreadable source, absent source, absent blob, malformed anything — falls back to an identical 202**, so the mount cannot probe existence); PATCH chunks with `Content-Range` continuity (416 on out-of-order); PUT commit with optional final chunk — **digest verified by the driver, and a mismatch publishes nothing and forgets the session**, no blob, no row, no retry into half-verified state; GET status; DELETE cancel; HEAD/GET blob streaming through `VerifiedReader`. Upload **rows land before sessions and blob rows before row deletion** (ADR 0010: content is pinned or recorded at every instant); sessions are **repository-bound by their row**, so an id replayed under another writable repository answers unknown; a row whose staged bytes vanished answers unknown too (restart → client re-pushes). Concurrent same-digest pushes both succeed; proxy repositories answer DENIED by type (ADR 0005); an absent repository and a hidden one answer byte-identically; a store that cannot answer is a spec-shaped 500, never a confident "unknown"; meta↔blob drift on read is a 500, never a lie (P-012's scrub). Quota is the stubbed `QuotaChecker` seam — a refusing stub proves start, monolithic, and chunk paths all consult it (P-009 lands enforcement without handler changes). **serve wires the hosted half** of fs or S3 storage at a disjoint root chosen at wiring time (ADR 0009); the live test proves the /v2/ tree speaks the spec envelope over real HTTP (the unrotated admin's push refused as DENIED naming the rotation). **Deviations:** blob-existence disclosure via HEAD is accepted — ADR 0006's `blobs` table is global by design, digests are content hashes, and probing still requires a readable repository; the official conformance suite runs with R-009 (a live full push additionally waits on C-016's repository-creation API — repositories are explicit entities, and none can be created over HTTP yet). Coverage 95.3% overall; CI green (run 33803412338)

## R-002 — Manifest put/get/delete + media-type validation

`internal/artifact/{mediatypes,parse}.go` + `internal/registry/manifests.go` + `registry.max_manifest_bytes` (config, default 4MiB) + serve wiring. **The parser is the edge** (`internal/artifact`): a closed set of four manifest media types (OCI manifest/index, Docker v2 manifest/list — schema 1 refused by absence), Content-Type and payload `mediaType` must agree where both exist and either may stand in for the other, every descriptor digest passes the strict allowlist parser before it can reach a query, and `subject` is honored **only on OCI types** — the Docker schema has no such field, and honoring one there would create attachments no Docker client asked for. `artifactType` resolves per spec v1.1: the explicit field, else the config media type (which is how a helm chart labels itself with no special casing). Foreign layers (`urls`) are marked external: not verified, not edge-recorded — the registry neither stores nor GCs them. **PUT** caps the payload before parsing (`MANIFEST_INVALID` naming the limit), computes the digest in the reference's own algorithm so a sha512 push cannot be mis-stored, refuses a mismatched digest reference with nothing published, and verifies **every referenced blob and index child exists** before the write — `MANIFEST_BLOB_UNKNOWN` naming the missing digest — plus a descriptor whose size contradicts the blob row (`MANIFEST_INVALID`; a size that lies breaks clients). The subject is deliberately exempt (spec: attachments may arrive before their subject) and echoed in `OCI-Subject`. Manifest and edges land in one transaction (ADR 0010); the tag repoints after. **GET/HEAD** serve the exact stored bytes under the stored media type and re-hash the payload on the way out: a row that no longer matches its digest is a 500, never content, and a tag pointing at a vanished row is the same 500, never "unknown" (ADR 0007; P-012's scrub). **DELETE** is digest-only (by tag answers `UNSUPPORTED` — tag deletion is R-003's, and the message says to use the digest); it collects the transitive referrer tree, pre-checks **Q10 across the whole tree and fails closed before deleting anything** — a member still listed by a live index outside the tree refuses the cascade naming that index — then deletes deepest-first (the signature dies before the SBOM, the subject last), so a crash mid-walk leaves only orphans for GC's sweep, never a dangling reference (ADR 0011); a store-level `ErrReferenced` race gets the same DENIED. Cascade proven three levels deep with the tag gone; index delete releases children for individual deletion. **Verbs:** `manifest:delete` enforced at the route — carol with `repo:write` and rita with `repo:read` both refused, anonymous gets the challenge — taking **`manifest:delete` off the §9 pending list (24 left)**. Hidden and absent repositories answer byte-identically on every manifest route; proxy repositories refuse PUT and DELETE by type (message generalized to "does not accept client writes" since deletes are writes too). Every store failure is a spec-shaped 500 through the same faulty-store harness as R-001. **Deviations, stated:** the per-referrer cascade audit records ADR 0011 asks for await the audit log (E-009 — `internal/audit` is still a doc stub), and `artifact.pushed`/`artifact.deleted` events await the bus (E-001); the enforcement contract is noted here rather than silently dropped. Coverage 95.3% overall; CI green (run 33873869803)

## R-003 — Tag list + pagination (permission-filtered)

`internal/registry/tags.go` — `GET /v2/<name>/tags/list` under `repo:read` (ADR 0002: listing tags is reading the repository). The page is a filtered query end to end: bindings → `VisibilityFor(repo:read)` → `ListTags`, with the store's not-found — unreadable and absent alike — mapped to the byte-identical guard 404, proven body-and-headers in both the handler suite and the now-unskipped Z-018 surface-2 test (`test/disclosure/tags_test.go` runs the real guard + real handler; **"tag list endpoint" off the disclosure skip-list**). Pagination is the spec's `n`/`last` with keyset cursors: a 25-tag stitching test proves pages concatenate to the full lexical set with no duplicates or gaps and no `Link` on the last page; `n` is echoed in the `Link` only when the client sent one, its query values escaped because a cursor is stored data being concatenated into a URL; `n=0` and absent both mean the store default (a zero page with a cursor is an infinite loop, not an answer), and a present-but-malformed `n` is a 400 `UNSUPPORTED` rather than a silent different page size. Empty repository answers `"tags":[]`, never null. A missing context subject fails closed to an empty visibility (no branch that could be wrong in the unsafe direction); a repository vanishing between resolution and listing answers the ordinary 404, not a 500. Store failures are spec-shaped 500s through a tags-local faulty store. Built by a parallel worktree agent against the frozen R-001/R-002 seams; reconciled with serve wiring here. **Deviation/left-open:** tag *deletion* (the spec's `DELETE /v2/<name>/manifests/<tag>`) remains `UNSUPPORTED` from R-002 — the route table's one-verb-per-route rule cannot express tag-vs-digest verb selection on a single route, so wiring `tag:delete` needs a deliberate routing split (constrained reference matching → two routes, one verb each), noted on the §9 allowlist entry; protected-tag gating belongs to P-001 regardless. No new verb marks (repo:read was already covered both ways). Coverage 95.1% overall; CI green (run 33878829309)

## R-005 — Referrers API (v1.1)

`internal/registry/referrers.go` — `GET /v2/<name>/referrers/<digest>` under `referrer:read`, with the ADR 0002 conjunction enforced in the handler: `repo:read` on the repository holding the subject is checked through the same bindings a pull would use (the `mount` sub-decision pattern), and its refusal is the byte-identical hidden 404 — **checked before the digest even parses**, so a malformed digest against an unreadable repository cannot confirm the repository exists. The §9 case is a named test both in the handler suite and in the now-unskipped Z-018 surface-3 test (**"referrers listing" off the disclosure skip-list**): a subject holding `referrer:read` without `repo:read` asking about `secret/vault` gets an answer indistinguishable, body and headers, from asking about `secret/absent` — an SBOM inherits its image's permission. Response is an assembled (never stored) OCI image index; descriptors carry mediaType/digest/size always and artifactType/annotations by `omitempty`, annotations lifted from the stored payload by a one-field unmarshal in the handler (`internal/artifact` stays about what the registry validates); `manifests` renders `[]`, never null, including for a digest never pushed — the spec's answer and the disclosure-safe one. `?artifactType=` filters via the store's indexed query with `OCI-Filters-Applied` set exactly when a filter was applied, matches or not. Full-body golden pinned; **`ListReferrers`'s digest ordering promoted from accident to contract** during reconcile (interface doc + metatest assertion — all three engines already complied) because a golden over store-dependent order would make identical registries answer differently. **`referrer:read` off the §9 pending list (23 left)**, positive at the round trip, negative at rita's 403 (readable-but-unattached refusal). Anonymous gets the challenge; bindings-store failure during the sub-decision is a fail-closed 500. Built by a parallel worktree agent; reconciled with serve wiring here. Coverage 95.2% overall; CI green (run 33878829309)

## R-011 — Stale upload-session reaping

`internal/registry/upload_reaper.go`: `UploadReaper` over a two-method meta slice (`ListStaleUploads` + `DeleteUpload`) and the package's own `BlobStore` — there is no method through which it could reach a manifest, tag, or blob row, so ADR 0009's hosted-side claim holds by construction, and `TestReaperNeverTouchesCommittedBlobs` proves it anyway (ten-year clock, 1ns TTL, committed blob survives). **Deletion order is the design**: staging cancelled first, row second — a crash between the two leaves a row whose staging is gone, which the upload handlers already answer as `BLOB_UPLOAD_UNKNOWN` and the next sweep clears; the inverse order would strand staged bytes nothing could ever list again, and a test asserts the wedged case leaves the row (proving the order was not inverted). `ErrNotFound` from either side is success — a concurrent commit or cancel got there first — asserted via sentinels, never text. Batching pages 256 at a time until a short page, with two loop guards (ctx at each page; a full page reclaiming zero breaks rather than relisting forever); per-session failures are logged, skipped, and `errors.Join`ed so the sweep finishes and the caller still learns it was incomplete. Activity protection is structural: `UpdateUpload` refreshes `last_chunk_at`, so an active session is simply not listed — proven through the real PATCH handler with the reaper run an hour past the original staleness point. The reap-vs-PATCH race answers 404 with no partial resurrection. `Run(ctx, interval)` is the interim ticker (immediate sweep, then per tick, channel-observed tests with no sleeps); P-006's scheduler replaces it and calls `ReapOnce`. **Wiring (reconcile):** `registry.upload_session_ttl` (default 24h, validated positive, example + operator docs) and serve's hourly loop tied to the shutdown context and drained after the listener stops, sharing the exact store values the handlers got. No reap-interval knob on purpose — it is an implementation detail P-006 removes. Coverage 95.3% overall.

## R-012 — Push-latency benchmark

Four benchmarks drive the real router and guard (`internal/registry/bench_test.go`, `bench`-prefixed fixture mirroring `newStack`): monolithic 1MiB and 100MiB blob pushes (the big one skips under `-short`), a chunked push, and a manifest PUT. The details are where the honesty lives: blob benches rebuild the stack per iteration outside the timer so the in-memory store cannot grow with b.N, digests are unique per iteration so the content-addressed no-op path is not what gets measured, and the manifest bench rotates a 256-entry payload pool because an unbounded working set was measurably timing map resizing (12% spread → 4%). **The gate** (`scripts/bench-check.sh`): duration-based `-benchtime` rather than a pinned count — these benchmarks span four orders of magnitude and one count starves the fast ones of samples — and best-of-N because benchmark noise is one-sided (a co-tenant only makes you slower), with a 20% exclusive boundary. Exit 0 pass/record, 1 regression, 2 malformed input; a malformed baseline line is fatal because silently skipping it would disable the gate for that benchmark; a partial baseline still enforces what it covers. A 39-assertion self-test (hermetic via canned input; verified with dockerized shellcheck) runs first in CI. **The baseline ships absent by design**: numbers must come from CI runner hardware, so the first run prints and uploads `bench-baseline-candidate`; the operator commits it as `scripts/bench-baseline.txt` and the job enforces from then on (re-baselining is the same three steps — the artifact uploads on every run). The CI `bench` job is separate and parallel; nothing about existing jobs changed. Deferred: the scan-backlog p50 test needs S-003's queue (noted in the file header). The agent's realism caveats are recorded for follow-up: in-memory stores measure our code rather than fs/S3+fsync, httptest bypasses the socket and chunked transfer, authn is free in the fixture, no concurrency benchmark yet — and if the gate ever flakes on a shared runner, widen the tolerance rather than retry, because a retried benchmark gate is a disabled one. Coverage 95.3% overall.

## R-010 — Pull statistics: last-pulled + counts

Two layers, one guarantee: the hot path never writes. **Meta:** `RecordPulls(ctx, []PullRecord)` batch-upserts in one transaction — counts add, `last_pulled_at` only moves forward however the batch is ordered — and `GetPullStats` reads one row (no listing on purpose; retention's P-tasks add one when they know their query shape). Migration 0003 in both engines creates `pull_stats` with **no foreign key, deliberately**: statistics are observations, not references, so a tag repointed or a repository deleted between the pull and the flush cannot fail the write; retention joins against live content when it evaluates. The tag column holds the reference — tag or digest, both count per the plan — with the bridge documented on the type and in the migration. SQLite's upsert uses a `CASE` for the timestamp (its two-arg `max()` NULLs out), Postgres uses `GREATEST`; schema parity holds. Contract cases cover accumulation, non-regression, per-reference rows, validation (`meta.Invalid` rejects the whole batch before anything is written), empty-batch no-ops, and both engines' dead-database/closed-store/cancellation failure tables pick the new methods up via `Calls`. **Registry:** `PullBatcher` (channel + one goroutine, aggregation map so a hot tag is one row per flush) flushes at 1000 distinct rows, on a 60s ticker, or on `Close` — injectable clock and tick channel, no sleeps in tests. Two drop policies, both deliberate and documented: a full queue drops the observation (a pull must never wait on a statistic; drops are counted and logged with queue depth), and a store error drops the batch (retrying into a broken store grows unboundedly exactly when memory is worth least). `Manifests.Pulls` is nil-safe; recording sits in GET after a successful resolve — **HEAD is a probe, not a pull**, and counting `docker manifest inspect` would hold tags alive against future last-pulled retention. The §9 proof: 50 GETs through the real HTTP stack against a call-counting store produce zero store calls, then one upsert carrying all 50 on close. **Wiring (reconcile):** serve constructs the batcher, hands it through `buildRouter`, and flushes it after the listener drains on a fresh timeout context — the shutdown context is already done, and a done context would silently drop the final batch — before the deferred store close. `artifact.pulled` emission is stated on the batcher as landing with E-001; a drop-count metrics accessor is a natural §8 follow-up. Coverage 95.4% overall.

## R-007 — Helm chart + SBOM artifact awareness

`internal/artifact/kinds.go` adds the vocabulary the UI, search, and gating need to say *what* an artifact is: `KindImage`, `KindIndex`, `KindHelmChart`, `KindSBOM`, `KindSignature`, `KindAttestation`, and `KindUnknown`. Classification reads the fields the parser already produced — an index is an index whatever it indexes; otherwise `artifactType` wins because that is the field the spec added for this question, and the config media type answers when there is none, which is the shape every image and every Helm chart has. Media-type **parameters are trimmed before matching** (cosign's bundle carries `;version=`, and matching whole strings would miss every future version), and prefix rules catch the versioned and vendor spellings ecosystems publish (`application/vnd.cyclonedx…` in both `+json` and `+xml`, `application/vnd.slsa…`, `application/vnd.dev.sigstore…`). **`KindOfStored(mediaType, artifactType)` is the entry point for stored rows**: because R-002's parser folds the config media type into `ArtifactType` when a manifest declares none, the two columns ADR 0006 already keeps are sufficient — no `kind` column, no migration 0006, and no second copy of the classification to disagree with the first. Every table case asserts the parsed manifest and the stored record classify identically, which is what pins that equivalence. **The rule the tests exist to hold:** classification is labeling and nothing else. No storage path, permission, or validation branches on a Kind, and `TestKindNeverGatesStorage` pushes an invented artifact type to prove it is stored verbatim and merely labelled `unknown` — a registry that only accepted types it recognised would stop being a registry the first time somebody invented a media type. `Kind.IsSignature` exists so ADR 0013's `unsigned: block` policy asks a question about meaning rather than carrying media-type strings of its own, which is how the two would eventually disagree about what a signature is; the registry round-trip pushes a chart, an image, an SBOM, a cosign signature and an index through the real handlers and counts exactly one signature among the image's two referrers. Binary-driven `helm push` / `oras attach` / `cosign` round trips against a live `trove serve` are R-009's harness, as with the docker integration deferred from R-001. Coverage 95.3% overall.

## R-009 — OCI conformance suite in CI

The official `opencontainers/distribution-spec` suite (pinned at v1.1.1) runs in a CI job against a real spawned `trove serve`: **73 of 73 applicable specs pass, 0 fail**, across pull, push, content discovery, and content management. Six specs skip — five the suite itself skips as optional, and the blob-delete follow-up trove declines by design (below). **The harness** (`test/conformance/`) exists because the suite can drive a registry but cannot stand one up: trove prints its admin password exactly once, refuses that account everything until it rotates (Z-014), and has no repositories until one is created (C-016). It builds the binary from the working tree rather than trusting one on PATH, finds a free port, captures the credential from stdout, rotates it, creates the entity, and runs the suite as a child process — the suite is a ginkgo binary configured from the environment at load time, so driving it in-process would mean setting global state and hoping. Its own **sanity test** is the project's first genuine push and pull over a socket (every earlier suite drove handlers in-process) and asserts the bootstrap contract the harness depends on, including that the one-time password never reaches the log stream: a red conformance run should mean the registry is wrong, and that test is what makes the inference sound. Locally the suite is a skip unless `TROVE_CONFORMANCE_BIN` points at the built binary, so `go test ./...` stays green on a machine that has never fetched it.

**The run paid for itself immediately by finding two real bugs.** First, **the authentication rate limiter charged successful logins**: burst 10 per account, and the conformance suite (like any `docker push` of a multi-layer image) mints a token per operation, so it was throttled to 429 mid-run and silently fell back to anonymous — every subsequent request then failed authorization. The limiter exists to make password *guessing* expensive, and a correct password is not a guess; `Limiter.Refund` and `AttemptLimiter.Succeed` now return the budget on success, so wrong guesses are charged exactly as before (the brute-force arithmetic is unchanged and pinned by a test that counts them) while a legitimate client is never cut off. The concession is on the address dimension — an attacker already holding one valid credential can refund their own successes and guess a little longer from that address — and it buys them nothing they could not do by authenticating legitimately. This was an availability bug wearing a security bug's clothes, and it would have hit the first operator to push a large image. Second, **blob deletion**: the spec makes it optional and signals "unsupported" with 405, but an unrouted DELETE answered 404 — which the suite reads as "the blob is gone" and then fails when the follow-up GET still serves it. trove declines blob deletion deliberately (a client deleting a blob directly can orphan a manifest that lists it; reclamation is GC's, which prefers leaking to losing — §7, ADR 0010), so the route now exists purely to say so honestly with 405, `Allow: GET, HEAD`, and a message naming garbage collection. The permission is still checked first, so the 404-vs-405 distinction discloses nothing to a subject who cannot see the repository. Group pull-side conformance is a tracked skip naming C-012, the way the disclosure suite's skips name theirs. Coverage 95.2% overall.

## R-003 (follow-up) — the tag/manifest DELETE route split

R-003 left tag deletion answering `UNSUPPORTED` and recorded why: the distribution spec overloads `DELETE /v2/<name>/manifests/<reference>` for two operations that destroy different things, ADR 0002 gives them different verbs, and the route table's one-verb rule could not express that on a single route. This is that split, built once the conformance suite (R-009) confirmed the spec is happy either way — it explicitly permits refusing tag deletion with 400 + `UNSUPPORTED`, so this was a product decision rather than a compliance one, and `tag:delete` being in the vocabulary (plus P-001's tag policies needing something to protect) settled it. **The router gained constrained placeholders**: `{reference:digest}` and `{reference:tag}` from a **closed** set of constraints, validated at registration so an unknown one panics at wiring time instead of becoming a route that silently never matches. The set is closed deliberately — arbitrary patterns in the route table would be a second matcher to disagree with the handlers, and the entire point here is that one wire path carries two permissions. `deleteTag` removes the name and leaves the content: the manifest still pulls by digest and its other tags still resolve, which is the distinction from `manifest:delete`'s cascade — untagging abandons an artifact to retention and GC, deleting destroys it and its referrers now, and a subject trusted to move tags is not thereby trusted to destroy what they point at. Both directions of non-implication are tested (each verb refused at the other's route, and `repo:write` refused at both), plus proxy refusal by type, unknown-and-illegal tags answering identically, and a store failure answering a spec-shaped 500. **One R-002 test had its premise rewritten rather than deleted** — it asserted the old `UNSUPPORTED` refusal, and now asserts what replaced it: `manifest:delete` alone reaches the tag route and is turned away there. P-001's protected and immutable tags belong in front of `deleteTag` when they land, noted at the handler. Conformance re-run after the split: still 73/73. Coverage 95.2% overall.
